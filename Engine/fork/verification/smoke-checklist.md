# Engine smoke checks

No desktop automation. These checks wait for the lead's Phase B approval.
Record actual log paths and results in the PR. Do not treat missing build
outputs in Phase A as a smoke pass.

## A. cefsimple launch (after every dev build)

Use the dev out directory from `VERSIONS`. Launch its `cefsimple` with
`--url=https://example.com --enable-logging=stderr --v=0` and capture stderr
to `$LOG_DIR/smoke-<date>.log`. Keep the launched PID. At 10 seconds require
that PID to be alive, then send SIGTERM to that PID only and wait for exit.
Inspect the log for `FATAL|Check failed`. Never terminate unrelated processes.

- [ ] The process starts and stays alive for 10 seconds; no `FATAL` or
  `Check failed` appears in stderr.
- [ ] example.com loads; its title or load-complete event is recorded in
  the log. For raw `cefsimple`, log-based proof is enough. For an Open-hosted
  view, capture only the app's own window.
- [ ] A second launch uses the same explicit profile directory without errors.
- [ ] Quit is clean. No child renderer from either launched PID remains.
  `pgrep -f cefsimple` is empty if no unrelated cefsimple session was present.

## B. Ad-block build glue (after Step 8, before service code)

- [ ] The exact target generated by `gnrt gen` builds alone under Chromium's
  pinned Rust toolchain (expected shape `third_party/rust/adblock/v0:lib`).
- [ ] `engine-status` S-7 still passes.
- [ ] Smoke A still passes. The PR states whether the crate is linked.
